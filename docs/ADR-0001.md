# ADR-0001 — Evidence-first architecture

Date: 2026-11-02
Status: Accepted for the first increment; to be revisited before auth and persistence.

## Decision
Preserve the existing accessible static frontend while introducing a minimal Node 22 HTTP service at the same origin. The server owns outbound research-provider requests, request validation, timeouts and normalized responses. This first increment is dependency-light and has no persistence or authentication. It is NOT approved for public multi-tenant production deployment.

## Endpoints
- GET /api/v1/health: liveness, no secrets.
- POST /api/v1/research: input {ideaName, ideaProblem, ideaSolution, ideaAudience, ideaKeywords}; output {query, retrievedAt, sourceStatus, sourceErrors, papers, repos, scope}.
- All other routes except explicitly allowlisted static assets return 404.

## Trust boundaries
- Browser inputs are untrusted. Maximum request body 12 KiB; text fields are validated and bounded.
- Only fixed OpenAlex and GitHub hosts are contacted. URL construction is server-controlled.
- If a user supplies explicit keywords, these are the ONLY search terms sent to providers. Otherwise a short locally derived query is sent. Users must be warned that search terms go to external services.
- No full founder description or private repository content is sent upstream.
- GitHub token is optional, server-only, and must not be logged or committed.
- Search errors are independent per provider; an unavailable provider is never mislabeled as 'nothing found'.
- No broad CORS policy, limited same-origin JSON POSTs, CSP and other response headers.
- In-memory per-IP rate limiting is only an early abuse guard. It is not distributed and NOT sufficient for internet-scale use.

## Evidence model
Every retrieved item contains source, URL and retrievedAt; academic publication years are retained where available. These are search hits, not proven matching inventions. An AI or analyst interpretation must be a separate reviewed object with source excerpt, source date, uncertainty and human review history.

## Rejected shortcuts
- No unsupported uniqueness percentage.
- No "patentability approved" or definitive legal answer from an LLM.
- No unprotected storage of confidential source code or contracts.
- No static frontend pretending successful research when providers fail.

## Future upgrade
Adopt authenticated tenant-scoped data persistence and a queued search orchestration service, with structured provider adapters, privacy protections and auditable human-reviewed claim charts. Next architectural decision records must cover identity, multi-tenancy, user-data deletion and patent-data licensing.
