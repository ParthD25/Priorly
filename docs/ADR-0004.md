# ADR-0004 — Dedicated Postgres and row-level security migration gate

Date: November 2, 2026. Status: Schema and CI tests prepared, NOT deployed or connected to the app.

Priorly must use a dedicated database/project. Connected BlueCore and Prysm Style projects are unrelated, and are not touched.

The baseline `infra/postgres/001_priorly_schema.sql` assumes Supabase Postgres and auth.uid()/auth.users. All user-facing tables use owner_id checks in SELECT, INSERT, UPDATE, and DELETE policies as appropriate. Composite foreign keys prevent connecting claim evidence across projects or owners, even within a single user's account. Research runs are append-only for ordinary users. The audit-events table has RLS enabled but NO ordinary client access grants or policies. No authorization uses editable user metadata.

GitHub Actions boots an isolated Postgres service and runs the migration and SQL security tests under stubbed Supabase Auth functions. Tests check cross-tenant reads, updates, spoofed insert attempts, cross-project evidence mappings, audit visibility and anon denial. These are integration tests for Postgres; they are NOT a verified Supabase Auth/PostgREST deployment.

Production release gate: provision standalone Priorly project and approve billing, apply migrations with proper tooling, run advisors, test with two real Auth users, integrate hosted auth and Postgres data adapter, implement password reset/MFA/session renewal, encrypted storage, audit writes, backups, cross-tenant permissions, retention/deletion and distributed rate limiting. The SQLite app continues to be localhost-only and refuses production mode. Confidential IP must not be entered until security review is complete.
